# Groucho pilots

Proposed experiments for extending Groucho into new use cases. These documents
describe concepts and validation plans, not shipped functionality or confirmed
partner commitments.

Start with the [ticket-access product direction](./ticket-access-direction.md) and
the [Fi discovery demo plan for 23 October](./fi-demo-2026-10-23.md). The meeting is
provisional; the plan distinguishes working prototype behaviour from simulations.
See the [implementation and rehearsal guide](./fi-demo-implementation.md) for the
current working simulation slice and the remaining Ezra scenario preparation.

Following the 16 October founder discussion, the immediate focus is an
**illustrative Ezra Collective operator workflow: suspicious clusters → applicant
review → fair ballot**. Discovery comes before the demo. World ID is optional;
ticketing demand, buyer ownership and integration economics still need validation.
The older verification concepts below remain research options, not Friday's build scope.

| Pilot | Status | Purpose |
| --- | --- | --- |
| [Fair ticket access with World ID](./fair-ticket-access-world-id.md) | Concept — 14 October 2026 | Combine unique-human verification, artist-led conversation, fair allocation and controlled resale |
| [Verified fan registration and assisted review](./verified-fan-registration.md) | Concept — 16 October 2026 | Test social-account control, progressive human checks, Groucho review and protected allocation with less enrolment friction |
| [Consumer-goods drop: Vans example](./consumer-goods-drop-vans.md) | Synthetic demo — 16 October 2026 | Review registrations and suspicious clusters, then run equal-chance ballots against stock by shoe size |
